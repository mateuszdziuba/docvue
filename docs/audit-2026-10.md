## 5. Native (Capacitor) — TODO, poza zakresem tego etapu

**Werdykt: obecna konfiguracja nie zbuduje działającej aplikacji.**
1. Brak `webDir` (default `www`); przy `server.url` sync po cichu nie kopiuje nic. `dist/client` nie ma `index.html` (tylko `_shell.html`) — bundled wymaga `spa.prerender.outputPath: '/index'`.
2. iOS: brak `NSAppTransportSecurity` (ATS blokuje LAN http) i `WKAppBoundDomains` przy `limitsNavigationsToAppBoundDomains: true`.
3. Android: targetSdk 36 bez `usesCleartextTraffic`/network config → `ERR_CLEARTEXT_NOT_PERMITTED`; `server.cleartext` ignorowane przez runtime.
4. `android/` i `ios/` w `.gitignore`, brak `cap add` — fresh clone nie zsynchronizuje.
5. Brak pluginów (camera/share/filesystem/push), `window.print()` i pobieranie blobów to no-ops w WebView, brak `NSCameraUsageDescription`.
6. `VITE_SITE_URL=localhost` psuje zaproszenia w produkcji.
7. Remote-URL shell = ryzyko odrzucenia w App Store (4.2), brak offline/pinningu.

Plan naprawy native (osobne zadanie): decyzja bunded vs remote-shell → `webDir`/index.html → ATS/cleartext/network config → tracked projects + skrypty `cap add` → pluginy zależnie od funkcji → testy na urządzeniach.

## 7. Status realizacji (branch `audit-fixes`)

### Zrobione — bezpieczeństwo
- `supabase/migrations/20261010_security_rls_hardening.sql` — **wymaga uruchomienia w Supabase** (SQL Editor / `supabase db push`). Usuwa publiczne polityki `USING(true)` na `client_forms`, `submissions`, `forms`, `treatments`, `treatment_forms`, `beauty_plans`, `scraped_products_cache`; scope'uje bucket `visit-photos` po salonie i ustawia limity MIME/rozmiaru.
- Kod serwerowy czyta/zapisuje dane publiczne (token formularza, plan, cache scrapowania, katalog zabiegów w czacie) klientem service-role po walidacji; jawne kolumny zamiast `select('*')` (koniec wycieku `pin_code`).
- Tokeny formularzy: `crypto.getRandomValues` (rejection sampling) — `lib/secure-token.ts`.
- Cookies sesji: przekazywane opcje `@supabase/ssr` (maxAge/sameSite/path/secure) — `src/utils/supabase.ts`.
- Filtry `salon_id` dodane w: clients, forms, treatments, appointments (create/delete/get), submissions (get/delete), client-forms (assign/list/delete), treatment_forms.
- `bookAsClientFn`: wymusza salon klienta, waliduje przynależność zabiegu; `createAppointmentFn` waliduje klienta i zabieg.
- SSRF scrapera: ręczne redirecty z walidacją każdego hopu, blokada CGNAT/IPv4-mapped, tylko porty 80/443, wymagane logowanie + rate limit.
- WhatsApp webhook: weryfikacja `X-Hub-Signature-256` (HMAC, timing-safe), bez echowania błędów; wymagany `WHATSAPP_APP_SECRET`.
- Rate limiting (in-memory, per instancja): login, rejestracja, reset hasła, token lookup, submit formularza, booking, czat, scrape; PIN lockout 5 prób/30 s.
- Czat: limit długości wiadomości, `targetSalonId` wyłącznie z sesji klienta.
- Staff invite: weryfikacja zgodności e-maila przy linkowaniu; ban przy usunięciu pracownika.
- Podpisy renderowane tylko jako `data:image/(png|jpeg|webp)`, `referrerPolicy="no-referrer"`.
- Nagłówki: HSTS, Permissions-Policy, CSP `Report-Only` (do enforce po testach).

## 8. Deploy na Vercel (naprawa)

Poprzedni produkcyjny deploy (marzec 2026) dotyczył starej aplikacji Next.js — migracja na TanStack Start była niezacommitowana, więc pierwszy deploy nowej wersji failed. Naprawa:

- **CVE-2026-102989 (XSS, CVSS 9.3)**: aktualizacja `@tanstack/react-start` 1.167.57 → **1.168.60**, `@tanstack/react-router` → 1.170.41, `@tanstack/start-server-core` → **1.169.39** (wszystkie ścieżki w lockfile). Vercel blokował deploy komunikatem o podatnej wersji.
- **Nitro** (`nitro@3.0.260903-beta`) dodany do `vite.config.ts` (`nitro/vite`) — wymagany przez Vercel dla TanStack Start; na Vercel auto-wykrywany preset `vercel`, lokalnie `node-server` (`.output/`).
- **`vercel.json`**: dodane `"framework": "tanstack-start"` (projekt miał preset Next.js), usunięte błędne rewrites do nieistniejącego `/index.html`.
- **Tryb SPA wyłączony** (`spa.enabled` usunięte) — SPA generowało `_shell.html` bez `index.html` i zwracało 404; standardowy SSR + Nitro obsługuje trasy i `/_serverFn/*`.
- `.output`/`.vercel` dodane do `.gitignore`.
- Weryfikacja lokalna: build exit 0, `node .output/server/index.mjs` → `/`, `/login`, `/forgot-password`, `/f/:token` = 200.
- Po deployu: usunąć ewentualne `DANGEROUSLY_DEPLOY_VULNERABLE_TANSTACK_START_XSS` z env Vercel (już niepotrzebne).
